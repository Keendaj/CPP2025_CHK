# Calculator

Шевцов Дмитрий Александрович — небольшой калькулятор на C++ с поддержкой внешних операций/функций через DLL-плагины.

**Коротко:** Сборка выполняется через CMake + Ninja. Все исходники располагаются в папке `source/`.

**Требования**
- CMake >= 3.16
- Ninja
- C++17 или выше
При несоблюдении требований нет гарантии в правильной работе программы, Ninja также является частью требований
---

## Сборка (cmd.exe)
1. Откройте `cmd.exe` в корне репозитория.
2. Создайте каталог сборки и выполните CMake (используется генератор Ninja):

\`\`\`bat
mkdir build
cd build
cmake -G "Ninja" ..
cmake --build . --config Release
\`\`\`

Если хотите пересоздать чистую сборку, удалите `build` и выполните шаги заново.

## Сборка (PowerShell)

\`\`\`powershell
Remove-Item -Recurse -Force build -ErrorAction SilentlyContinue
New-Item -ItemType Directory build
cd build
cmake -G "Ninja" ..
cmake --build . --config Release
\`\`\`

После успешной сборки исполняемый файл `calculator.exe` появится в каталоге `build`.

## Плагины (пользовательские функции / операции)
- Место для плагинов в репозитории: `source/plugins/`.
- При сборке CMake автоматически скопирует содержимое `source/plugins` в директорию рядом с вашим бинарником (см. `CMakeLists.txt`).
- В `source/plugins/` уже лежат примеры (DLL): функции `cos`, `log`, `sin`, `sqrt` и оператор `^` (возведение в степень).

Чтобы добавить свою функцию/операцию:

1. Напишите DLL (Windows) с экспортируемыми C-функциями (см. интерфейс в `source/IPlugin.hpp`).
2. Экспортируемые функции, которые должны присутствовать в DLL:
   - `const char* getName() noexcept;` — имя операции/функции (строка), которое используется в выражениях, например `"sin"` или `"^"`.
   - `bool isOperation() noexcept;` — возвращает `true`, если плагин представляет бинарную операцию (например `^`).
   - `bool isFunction() noexcept;` — возвращает `true`, если плагин — унарная функция (например `sin`).
   - `size_t getPrecedence() noexcept;` — приоритет операции (для операций) (большее число — выше приоритет).
   *Функциями в данном случае считаются функции одной переменной, которые используются префиксным способом. Операторы это функции двух переменных, которые используются инфиксным способом.
   - `void getCalculation(calculator::number* operands, size_t* count);` — выполняет расчёт: получает массив `operands` и указатель на `count` (число операндов, которые переданы), должен заполнить массив результатами и выставить `count` равным числу возвращаемых элементов (обычно 1).

3. Вы можете использовать исключения из `source/utils/Exceptions` для передачи ошибок из плагина.
4. Соберите DLL (например, с помощью MSVC/Visual Studio или CMake). В процессе сборки определите макрос `PLUGIN_EXPORTS`, чтобы `IPlugin.hpp` мог экспортировать символы (`__declspec(dllexport)`).
5. Поместите готовую `.dll` в `source/plugins/` — при следующем запуске/сборке приложение сможет её загрузить.

Пример простого скелета плагина (файл `myplugin.cpp`):

\`\`\`cpp
#include "IPlugin.hpp"
#include <cmath>

#ifdef PLUGIN_EXPORTS
    #define EXPORT __declspec(dllexport)
#else
    #define EXPORT
#endif

extern "C" {
    EXPORT const char* getName() noexcept { return "square"; }
    EXPORT bool isOperation() noexcept { return false; }
    EXPORT bool isFunction() noexcept { return true; }
    EXPORT size_t getPrecedence() noexcept { return 0; }

    EXPORT void getCalculation(calculator::number* operands, size_t* count) {
        if (*count >= 1) {
            operands[0] = operands[0] * operands[0];
            *count = 1;
        }
    }
}
\`\`\`

Примечание: при использовании MSVC можно собрать DLL через CMake или напрямую командой `cl` (пример):

\`\`\`bat
cl /LD /DPLUGIN_EXPORTS myplugin.cpp /Fe:myplugin.dll
\`\`\`

## Советы по отладке плагинов
- Убедитесь, что имена экспортируемых функций точь-в-точь совпадают (`getName`, `isOperation`, `isFunction`, `getPrecedence`, `getCalculation`).
- Экспортируйте функции с `extern \"C\"`, чтобы избежать манглинга имён.
- В плагине корректно обрабатывайте количество операндов: приложение передаёт до двух операндов для бинарных операций.
- При ошибках загрузки плагинов приложение бросит исключения типа `calculator::LoadException` / `calculator::DLLException` — посмотрите вывод для диагностики.

## Тесты (подробно)

В проекте есть набор автоматических тестов (см. `source/Tests/Test.cpp`). Ниже перечислены все тесты и их назначение — это помогает понять, какие сценарии покрыты и зачем нужны проверки.

- Parser - обычная работа (\"парсинг 2 + 3 * 4\"): проверяет, что парсер корректно преобразует инфиксное выражение в RPN с учётом приоритета умножения. Ожидаемая RPN: `\"2 3 4 * + \"`.
- Parser - функции (\"sqrt(16) + cos(0)\"): убеждается, что парсер обрабатывает вызов функций и размещает их в RPN после аргументов: ожидается `\"16 sqrt 0 cos + \"`.
- Parser - унарный минус (\"-3 + 5\"): проверяет корректную обработку унарного минуса (преобразуется в `0 3 - 5 +`). Это важно, чтобы выражения с отрицательными числами не интерпретировались как бинарная операция.
- Parser - скобки (\"2 * (3 + (4 - 1))\"): тестирует, что вложенные скобки учитываются корректно, и порядок операций в результирующей RPN соответствует ожиданию `\"2 3 4 1 - + * \"`.
- Parser - операция из DLL (\"2 ^ 3 + 4\"): убеждается, что парсер распознаёт нестандартную операцию (загружаемую из плагина) и корректно включает её в RPN: `\"2 3 ^ 4 + \"`.

- Calculation - обычная работа (\"2 + 3 * 4\"): выполняет вычисление и сравнивает числовой результат с ожидаемым (`14`). Это проверяет весь путь: парсер -> вычислитель.
- Calculation - функции (\"sqrt(16) + cos(0)\"): проверяет правильный числовой результат при использовании функций (ожидается `5`, т.е. `4 + 1`).
- Calculation - унарный минус (\"-3 + 5\"): проверяет, что результат с унарным минусом равен `2`.
- Calculation - скобки (\"2 * (3 + 4)\"): проверяет числовой результат (`14`) при наличии скобок.
- Calculation - операция из DLL (\"2 ^ 3 + 4\"): проверяет, что выполняется операция из плагина и итоговый результат равен `12`.

- DllLoader - загрузка всех плагинов: создаёт `DllLoader(\"plugins\")` и вызывает `loadPlugins()`. Тест подтверждает, что плагины можно найти и хотя бы один успешно загрузился.
- DllLoader - проверка типа функции: убеждается, что функция вроде `sin` помечена как функция (`isFunction(\"sin\") == true`) и не считается операцией.
- DllLoader - проверка типа операции: убеждается, что операция вроде `^` помечена как операция (`isOperation(\"^\") == true`) и не является функцией.
- DllLoader - выполнение функции `cos(0)`: подготавливает стек с одним аргументом `0`, вызывает `execute(\"cos\", stack)` и проверяет, что результат близок к `1` и стек содержит ожидаемое количество элементов.
- DllLoader - операция возведения в степень `^` (2^3 = 8): подготавливает стек `2, 3`, вызывает `execute(\"^\", stack)` и проверяет, что результат равен `8`.
- DllLoader - `sqrt(16)`: проверяет, что `execute(\"sqrt\", ...)` возвращает `4`.
- DllLoader - `log(1)`: проверяет, что логарифм возвращает `0` (с допуском), тем самым проверяя корректность функций с нулевым/специальным значением.
- DllLoader - приоритет операции: вызывает `getPrecedence(\"^\")` и убеждается, что приоритет не равен нулю (т.е. плагин предоставляет осмысленный приоритет для операции).
- DllLoader - смена пути плагинов: проверяет, что `setPluginsPath()` правильно меняет путь и `getPluginsPath()` возвращает новый путь.
- DllLoader - обработка несуществующего плагина: вызывает `isFunction(\"nonexistent_plugin\")` и ожидает выброса `calculator::DLLException` — проверяет корректную обработку неизвестных имён плагинов.
- DllLoader - выгрузка плагинов: вызывает `unloadPlugins()` и затем проверяет, что доступ к ранее загруженным плагинам больше невозможен (ожидается `DLLException`).

Эти тесты покрывают:
- корректность парсинга инфиксной записи в RPN (включая скобки, функции и унарный минус),
- корректность числовых вычислений (включая вызов функций и операций из DLL),
- работу загрузчика плагинов: поиск, загрузку, проверку типов, выполнение, получение приоритетов, смену пути и корректную обработку ошибок.
